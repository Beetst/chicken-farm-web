🔎 AI / LLM ค้นหาข้อมูลอย่างไร?

สื่อการสอนแบบโต้ตอบ: ดูเส้นทางของ “คำถาม” ตั้งแต่พิมพ์ จนวิ่งผ่านเครือข่ายอินเทอร์เน็ต ฐานข้อมูลเวกเตอร์ และกลับมาเป็นคำตอบ

1. LLM “รู้” อะไร และทำไมต้องค้นหา

ความรู้ในตัว

Parametric Memory

LLM เรียนจากข้อความจำนวนมหาศาล แล้วเก็บรูปแบบภาษาไว้ใน “น้ำหนัก” (parameters) แต่ความรู้หยุดอยู่ที่วันตัดข้อมูล (knowledge cutoff)

ปัญหา

ข้อมูลเก่า / มโน

ถ้าถามเรื่องใหม่หรือเฉพาะทาง โมเดลอาจตอบผิดอย่างมั่นใจ เรียกว่า Hallucination

ทางแก้

RAG + Tool Use

ให้โมเดล “ไปค้นก่อนตอบ” (Retrieval-Augmented Generation) ทั้งจากเว็บและฐานข้อมูลขององค์กร แล้วนำผลมาใส่ในบริบท

2. จำลอง: คำถามวิ่งผ่านเครือข่าย

3. ลองตัดคำเป็น Token

LLM ไม่ได้อ่านเป็นตัวอักษร แต่แบ่งข้อความเป็นชิ้นเล็ก ๆ เรียกว่า token แล้วแปลงเป็นตัวเลข (ตัวอย่างนี้เป็นการจำลองอย่างง่าย)

4. ค้นหาแบบเวกเตอร์ (Semantic Search)

เอกสารและคำถามถูกแปลงเป็น Embedding (ชุดตัวเลขที่แทน “ความหมาย”) แล้ววัดความใกล้ด้วย Cosine Similarity — คำต่างกันแต่ความหมายใกล้กันก็หาเจอ

* คะแนนจำลองจากคำ/แนวคิดที่ซ้อนกัน เพื่อให้เห็นหลักการ

5. เปรียบเทียบวิธีค้นหา

วิธีหลักการข้อดีข้อจำกัด
Keyword (BM25)นับคำที่ตรงกันเร็ว แม่นกับชื่อเฉพาะไม่เข้าใจคำพ้องความหมาย
Vector Searchเทียบความหมายด้วย embeddingเข้าใจบริบท ข้ามภาษาได้อาจพลาดตัวเลข/รหัสเป๊ะ ๆ
Hybrid + Rerankรวมสองแบบ แล้วจัดลำดับใหม่แม่นที่สุดในงานจริงซับซ้อน ใช้ทรัพยากรมากกว่า
Web Search ToolLLM เรียก search engine ผ่านอินเทอร์เน็ตได้ข้อมูลล่าสุดต้องกรองแหล่งที่น่าเชื่อถือ
Agentic Searchค้นหลายรอบ คิด-ค้น-อ่าน ซ้ำตอบคำถามยากหลายขั้นได้ช้าและแพงกว่า
Knowledge Graph คืออะไร?

เก็บข้อมูลเป็น “โหนด” และ “ความสัมพันธ์” เช่น (ไก่) —ออก→ (ไข่) ทำให้ AI เดินตามเส้นเชื่อมเพื่อหาคำตอบหลายทอดได้ เรียกว่า GraphRAG

ทำไมต้องอ้างอิงแหล่งที่มา (Citation)?

เพื่อให้ผู้ใช้ตรวจสอบได้ว่าคำตอบมาจากเอกสารใด ลดความเสี่ยงจากการมโนของโมเดล

เครือข่ายอินเทอร์เน็ตเกี่ยวอะไรด้วย?

เวลาค้นเว็บ คำขอวิ่งผ่าน DNS (แปลงชื่อโดเมนเป็น IP) → HTTPS ไปยัง Search API → ได้ URL → ดึงหน้าเว็บจากเซิร์ฟเวอร์ต้นทาง (มักผ่าน CDN) → ส่งกลับมาเป็นข้อความให้โมเดลอ่าน
